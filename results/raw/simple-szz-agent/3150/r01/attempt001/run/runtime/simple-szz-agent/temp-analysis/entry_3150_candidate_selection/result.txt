SELECTED: candidate_53

CONFIDENCE: HIGH

EXPLANATION:
The fix commit ("bugfix: retargeting logic error") modifies Util.retargetAnimation/retargetTrack in
src/main/java/maud/Util.java. Before the fix, the code was:

    sourceTrack = MyAnimation.findTrack(sourceAnimation, iSource);
    if (sourceTrack != null) { // handle null sourceTrack
        BoneTrack track;
        track = retargetTrack(sourceAnimation, sourceTrack,
                sourceSkeleton, targetSkeleton, mapping, iTarget);
        result.addTrack(track);
    }

The fix removes this null-guard entirely and instead always calls retargetTrack, pushing the
null-handling into retargetTrack itself (which now synthesizes a single bind-pose keyframe when
sourceTrack is null, instead of silently omitting the target bone's track altogether). The bug was
that any target bone mapped to a source bone with no corresponding animation track was completely
skipped when building the retargeted animation, rather than being given a bind-pose track — a
logic error in the retargeting process.

Tracing the history of this code in the candidates:

- candidate_36 contains an earlier version of retargetAnimation/retargetTrack where sourceTrack is
  looked up *inside* retargetTrack via sourceBoneIndex, with no null check at all (this would NPE on
  a missing track — a different bug, not the one described in the fix).

- candidate_53 refactors retargetTrack to take the already-resolved BoneTrack sourceTrack as a
  parameter, and at the call site introduces:
      sourceTrack = MyAnimation.findTrack(sourceAnimation, iSource);
      if (sourceTrack != null) {
          ...
          result.addTrack(track);
      }
  This is exactly the problematic "skip the track when null" logic that the fix later removes.
  Inside retargetTrack, candidate_53 also adds `Validate.nonNull(sourceTrack, "source track")`,
  reinforcing that null sourceTrack was being treated as an error/skip condition rather than a
  legitimate bind-pose case.

- candidate_54 only adds the comment "// handle null sourceTrack" to the same `if` line — no
  behavioral change.

- candidate_55 is identical to the fix commit diff itself (the actual bug fix), removing the
  null-check/skip behavior.

Since candidate_53 is the first commit to introduce the `if (sourceTrack != null) { ... }` skip
logic that the fix directly reverses, it is the bug-introducing commit.
