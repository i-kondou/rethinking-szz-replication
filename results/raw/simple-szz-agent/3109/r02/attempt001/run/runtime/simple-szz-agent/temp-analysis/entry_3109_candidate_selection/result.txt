EXPLANATION:
The fix commit modifies the single-selection branch inside SavedHqlExportToCSV.export()
(the "else" branch handling options that do NOT allow multi-selection, e.g. SUBJECT or
DEPARTMENT). Before the fix, the code unconditionally did:

    String value = helper.getParameter(option.name());
    SavedHQLInterface.IdValue v = new SavedHQLInterface.IdValue();
    v.setValue(option.name());
    Long id = option.lookupValue(context.getUser(), value);
    if (id == null) {
        try { id = Long.valueOf(value); } catch (NumberFormatException e) {}
    }
    v.setText(id == null ? "" : id.toString());
    params.add(v);

The bug: when `value` is null (the parameter was not actually supplied for this request,
e.g. because it's a single-choice HQL report parameter without a selection), the code
still built and added an IdValue with an empty/garbage text and no valid id, which broke
CSV export for reports containing a single-choice parameter. The fix wraps this whole
block in `if (value != null) { ... }` so no parameter entry is created when the value is
absent.

Tracing the history of this file across candidates:
- candidate_12's diff shows this exact block being added as brand-new code (`+` lines),
  including the single-selection "else" branch with `helper.getParameter(option.name())`
  followed immediately by unconditional IdValue creation/lookup/add — with no null check
  on `value`. This is the very first appearance of the buggy pattern.
- candidate_13's diff touches the same file (hash 035a4b20d..2f093afe5) but only adds a
  new SavedHQLParameter loop after this block; it does not modify or fix the
  single-selection branch, so the bug persists unchanged.
- candidate_14's diff is byte-for-byte identical to fix_commit_diff.txt (same blob hashes
  2f093afe5..857ee9502), meaning candidate_14 is actually the fix commit itself, not a
  bug-introducing candidate.

Since candidate_12 is the first commit to introduce the unguarded single-selection value
handling that the fix later corrects with the `if (value != null)` check, it is the
bug-introducing commit.
