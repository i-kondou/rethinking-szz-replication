EXPLANATION:
The fix commit (fix_commit_diff.txt) modifies the single-selection branch of
SavedHqlExportToCSV.export() by wrapping the existing logic in "if (value != null) { ... }".
Before the fix, the code was:

    String value = helper.getParameter(option.name());
    SavedHQLInterface.IdValue v = new SavedHQLInterface.IdValue();
    v.setValue(option.name());
    Long id = option.lookupValue(context.getUser(), value);
    if (id == null) {
        try { id = Long.valueOf(value); } catch (NumberFormatException e) {}
    }
    v.setText(id == null ? "" : id.toString());
    params.add(v);

This is exactly the buggy pattern: when a single-choice parameter such as SUBJECT or
DEPARTMENT is not supplied by the request (helper.getParameter(option.name()) returns
null), the code still unconditionally calls option.lookupValue(user, null), which (for
implementations like DEPARTMENT/SUBJECT that call value.equalsIgnoreCase(...)) throws a
NullPointerException, breaking the CSV export.

Searching all 14 candidates for this exact block, candidate_12 is the commit that FIRST
introduces it. Candidate_12 is a large refactor of SavedHqlExportToCSV.java that replaces
the old positional-parameter export logic with the new per-Option loop:

    for (SavedHQL.Option option: SavedHQL.Option.values()) {
        ...
        } else {
            String value = helper.getParameter(option.name());
            SavedHQLInterface.IdValue v = new SavedHQLInterface.IdValue();
            v.setValue(option.name());
            Long id = option.lookupValue(context.getUser(), value);
            if (id == null) {
                try { id = Long.valueOf(value); } catch (NumberFormatException e) {}
            }
            v.setText(id == null ? "" : id.toString());
            params.add(v);
        }
    }

This is byte-for-byte identical (modulo formatting) to the pre-fix code shown in
fix_commit_diff.txt, with no null-check on `value`. Candidate_12 also adds the
`lookupValue` implementations (e.g. DEPARTMENT: `value.equalsIgnoreCase(d.getDeptCode())`,
SUBJECT: `value.equalsIgnoreCase(s.getSubjectAreaAbbreviation())`), confirming that calling
these with a null `value` would throw an NPE — precisely the failure the fix commit
addresses.

Earlier candidates (candidate_01, candidate_05) only contain the older positional-index
based parameter logic (`v.setText(i < p.length ? p[i] : "")`) and do not yet have the
`option.lookupValue(context.getUser(), value)` call at all, so the bug did not exist in
those versions. Later candidate_13 adds unrelated SavedHQLParameter handling but leaves
this single-selection block untouched, and candidate_14 is the actual fix commit (it
matches fix_commit_diff.txt exactly), so it cannot be the introducing commit. This
confirms candidate_12 is the commit that introduced the bug.
