EXPLANATION:
The fix commit message says "Removes the round end data in preparation for mid-round loading. Also fixes a bug." The bulk of the fix diff is the large RoundEndData/event refactor, but the actual bug fix is a small, isolated change to core/src/de/gg/util/TickCounter.java: the fix removes the line `tickCount = maxTicks;` from the TickCounter constructor and simplifies the javadoc from "Creates a tick counter. Has to be reset() first to get used." to just "Creates a tick counter."

This reveals the bug: TickCounter's constructor initialized `tickCount` to `maxTicks` (i.e. already "finished") instead of leaving it at its default of 0. Looking at TickCounter#update(): the tick-processing loop is guarded by `tickCount < maxTicks`, so with `tickCount` starting equal to `maxTicks` no ticks are ever processed, and the very next check `if (tickCount == maxTicks) { if (!finished) { finished = true; return true; } }` fires immediately — causing update() to report the round as "over" on the first call after initialization, before any real ticks were counted. The old javadoc comment "Has to be reset() first to get used" was effectively documenting a workaround for this bug rather than a real design requirement.

candidate_81 is the commit that introduces TickCounter.java for the first time (new file, index 0000000..60e648f) and is the one that contains the line `tickCount = maxTicks;` in the constructor — exactly the line later deleted by the fix. It also wires up GameSession to use this new TickCounter (calling tickCounter.update() in update(), and only calling tickCounter.reset() inside startNextRound(), which happens after a round already ended) — meaning the very first update() call after game/session initialization would incorrectly report the round as finished immediately, matching the described bug.

No other candidate touches TickCounter.java except candidate_82, which is the commit that performs the actual bug fix (removing `tickCount = maxTicks;`) and matches the fix commit diff itself. Since candidate_81 is the sole commit that introduces the flawed initialization, it is the bug-introducing commit.
