EXPLANATION:
The fix commit changes RuleSet.java's getParents() override from:
  return SConceptOperations.getAllSuperConcepts(nextConcept, false);
back to:
  return SConceptOperations.getDirectSuperConcepts(nextConcept, false);

This getParents() method is used by SingleTermRules.computeRules() to do a
BFS/queue-based walk up the concept hierarchy, calling allForConcept() at each
node and adding that node's own getParents() result back into the queue. This
walker inherently expects getParents() to return only the DIRECT
superconcepts at each step, since it iterates the full transitive closure
itself one level at a time. Returning getAllSuperConcepts (all transitive
ancestors) at every step causes each ancestor to be re-enqueued redundantly
at every level, and more importantly it causes the walk to skip/short-circuit
the correct rule resolution order for overloaded-operator type rules (e.g.
"String += char"), because rules that should only match a direct supertype
end up being evaluated against the full transitive closure repeatedly,
producing the wrong result for the "+=" operator with a char operand and
triggering the reported type-system error.
