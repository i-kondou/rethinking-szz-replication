EXPLANATION:
The fix commit changes RuleSet.java's getParents() implementation from
`SConceptOperations.getAllSuperConcepts(nextConcept, false)` to
`SConceptOperations.getDirectSuperConcepts(nextConcept, false)`. The
getParents() method is used by SingleTermRules.computeRules() as the
BFS "parent" expansion function to walk up the concept hierarchy one
level at a time while collecting applicable typesystem rules. Feeding
it getAllSuperConcepts (which returns the full transitive closure of
ancestors, not just direct parents) instead of the direct parents
breaks the BFS traversal semantics and causes rules from certain
ancestor concepts to be looked up/overridden incorrectly, producing
exactly the kind of spurious typesystem error described in the bug
report (`String a="abc"; a+='d';` failing with a typesystem error,
since a compound-assignment/concatenation rule higher in the type
hierarchy is not resolved correctly).
